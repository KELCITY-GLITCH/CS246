1- Depth-First Search:
    Is a graph search method that explores as far as possible in one direction before going back and trying another path.

    Breadth-First Search:
    Is a graph search method that explores all close vertices before moving farther. 

    Graph:
    Is a data structure made of vertices and edges. The vertices represent points or objects, and the edges represent connections between them.

    Adjacent Vertices:
    Are vertices that are connected directly to each other by an edge, usually the cells directly above, below, left, or right of a cell.

2- In my own words the problem statement is asking to determine whether a program can find a valid path from one point in a two-dimensional grid to another point.
    The program must search through the grid while avoiding blocked locations and decide if the ending point can be reached from the starting point.

3- Forecasting

    a) Depth-first search explores one path as far as it can before backtracking and trying another path. Breadth-first search explores all nearby points first before moving farther away from the starting point. DFS goes deep first, while BFS goes level by level.


    b) Depth-first search usually uses a stack or recursion. Breadth-first search usually uses a queue. Both algorithms also need a way to keep track of visited points so the same location is not searched more than once.


    c)

    1. Start at the starting point.
    2. Push it onto a stack.
    3. Remove the top point from the stack while the stack is not empty
    4. The search is successful if the point is the ending point
    5. Mark it as visited if the point has not been visited
    6. Check each valid adjacent point.
    7. Push it onto the stack if an adjacent point is not blocked and has not been visited
    8. Continue until the ending point is found or the stack becomes empty.
    9. If the stack becomes empty, no path exists.


    d) 

    1. Start at the starting point.
    2. Enqueue into a queue.
    3. Remove the front point from the queue while the queue is not empty
    4. The search is successful if the point is the ending point
    5. Mark it as visited if the point has not been visited
    6. Check each valid adjacent point.
    7. Then enqueue it into the queue if an adjacent point is not blocked and has not been visited
    8. Continue until the ending point is found or the queue becomes empty.
    9. No path exists if the queue becomes empty

5- Step-by-Step Procedure

    a) This function checks the valid neighboring positions around point p in the grid g. 
    If a neighboring point is inside the grid, open, and available to visit, the function inserts that point into the front of the deque s.
    This helps the depth-first search choose which point to visit next.


    b) This function uses depth-first search to find a path from the start position of the grid to the end position. 
    It begins at the starting point, stores available points in a deque, and keeps searching through valid adjacent points. 
    If the end point is found, the function returns the path as a string. If no path exists, it returns an empty string.   

6. Implementation Notes

    The program was implemented using depth-first search. Deque object was used like a stack by inserting and removing points from the front. 
    Each search step stored both the current point and the path string used to reach that point.

    One important design decision was to create a Step structure that stores a Point and a string path.
    This was necessary because storing only Point objects would allow the program to visit locations, 
    but it would not remember the exact path taken to reach each location.

    A bug was encountered where the program originally returned an empty path for every test case. 
    The reason was that the start point was not treated as an available grid location by the available() method. 
    I fixed it by allowing the search to process the start point even if available() returned false for it.
